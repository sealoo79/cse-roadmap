# course_relations.json

## 이 데이터가 의미하는 것

**과목과 과목 사이의 "먼저 들어야 하는/듣기를 권장하는/함께 들어야 하는" 관계**를 한 줄씩 기록한 목록입니다. 한 줄이 화살표 하나(`from_code` → `to_code`)이고 총 25건입니다.
화살표를 이어 붙이면 로드맵 트리가 되고, 어떤 과목의 선수과목이나 이후 과목을 찾는 데 쓰입니다.

학과 문서에 적힌 관계만 담았습니다. 수강신청 시스템이 실제로 선수과목을 막는지는 확인하지 못했습니다.

```
course_relations.json ──(from_code / to_code)── courses.json
                      └─(program_id)── programs.json
```

## 서비스에서 쓰이는 기능

| 기능 | 사용하는 필드 | 쓰임 |
|---|---|---|
| 로드맵 생성: 선수 트리 화살표 (④) | `from_code`, `to_code`, `type` | 과목 카드 사이의 화살표를 그림. 과목을 선택하면 앞선 과목과 이후 과목 경로를 강조 |
| 수강 과목 추천: 선수 충족 판단 (②) | `from_code`, `to_code`, `type` | 선수과목을 이수한 과목을 "수강 가능"·"추천"으로, 이수하지 않은 과목은 "선수 미충족"으로 표시 |
| 필수 선후수 경고 | `type == "official"` | 이수체계 준수가 필요한 과목에 🔒 또는 "사전승인 필요" 안내 |
| 권장 순서 안내 | `type == "recommended"` | "먼저 듣기를 권장" 문구로 표시 (잠금 없이) |
| 동시수강 안내 | `type == "coreq"` | 자료구조/자료구조응용에 "함께 신청" 표시 (화살표가 아닌 묶음으로) |
| 과목 상세: 선수·후수 목록 | `from_code`, `to_code` | 과목을 눌렀을 때 "먼저 들을 과목"과 "이 과목 이후 과목" 표시 |
| 졸업 지연 위험 알림 (선택) | `from_code`, `to_code` | 어떤 과목을 놓치면 뒤 과목이 연쇄적으로 밀리는지 계산 (개설학기 데이터가 함께 필요) |

관계는 학생의 `program_id`와 `admission_year`가 `admission_year_from ~ admission_year_to` 범위에 들어가는 행만 사용합니다. 관계가 없는 전공(예: 첨단컴퓨팅연구)은 화살표 없이 학년 배치만 보여줍니다.

## 필드

| 필드 | 타입 | 설명 | 예시 |
|---|---|---|---|
| `id` | number | 관계의 일련번호 | `1` |
| `from_code` | string | **먼저 듣는 과목**의 과목코드 (`courses.json` 참조) | `"COMP0204"` |
| `to_code` | string | **나중에 듣는 과목**의 과목코드 (`courses.json` 참조) | `"COME0331"` |
| `type` | string | 관계의 종류 (아래 표) | `"official"` |
| `group_no` | number | OR 조건 묶음 번호. 같은 `to_code`에서 같은 번호는 "이 중 하나", 다른 번호는 "모두 필요". 종합설계프로젝트1(`ITEC0401`)의 선수 2건만 `1`과 `2`로 나뉘어 있고 나머지는 `1` | `1` |
| `program_id` | string | 이 관계가 적용되는 전공 (`programs.json`의 `program_id`) | `"platform_sw_data"` |
| `admission_year_from` | number | 적용 시작 입학년도 | `2023` |
| `admission_year_to` | number | 적용 마지막 입학년도 | `2025` |
| `source` | string | 근거가 된 문서 | `"심화컴퓨터공학프로그램(ABEEK) 2025 안내 …"` |
| `note` | string \| null | 원문 표기, 가정, 주의 사항 | `"원문: 프로그래밍기초 → 자료구조/자료구조응용 …"` |

### `type` 값

| 값 | 의미 | 서비스에서 처리 방식 (제안) | 건수 |
|---|---|---|---|
| `official` | 이수체계 준수가 필수인 선후수. 미준수 시 수강 전 사전승인 필요 | 🔒 잠금 또는 강한 경고 | 7 |
| `recommended` | 권장 이수 순서. 학생 진로에 따라 조정 가능 | "먼저 듣기를 권장" 안내 | 16 |
| `coreq` | 동시 수강 필수(블록강의). 순서가 아니라 같이 신청하는 관계 | "함께 신청" 안내 | 2 |

### `program_id`별 내용

| 값 | 전공 | 관계 |
|---|---|---|
| `platform_sw_data` | 플랫폼SW&데이터과학전공 | `official` 7건 (2023~2025) |
| `global_sw` | 글로벌SW융합전공 | `coreq` 1건 (2024~2025) |
| `ai_computing` | 인공지능컴퓨팅전공 | `recommended` 5건, `coreq` 1건 (2026) |
| `adv_computing` | 심화컴퓨팅전공 | `recommended` 11건 (2026) |

첨단컴퓨팅연구전공(`adv_research`)은 문서에 선후수 정보가 없어 관계가 없습니다.

## 예시

```json
{
  "id": 1,
  "from_code": "COMP0204",
  "to_code": "COME0331",
  "type": "official",
  "group_no": 1,
  "program_id": "platform_sw_data",
  "admission_year_from": 2023,
  "admission_year_to": 2025,
  "source": "심화컴퓨터공학프로그램(ABEEK) 2025 안내 \"이수체계 준수 필수 선후수 과목\" (미준수 시 수강 전 사전승인 필요)",
  "note": "원문: 프로그래밍기초 → 자료구조/자료구조응용 (2012학번부터 적용)"
}
```

읽는 법: 플랫폼SW&데이터과학전공 2023~2025학번은 **프로그래밍기초(COMP0204) → 자료구조(COME0331)** 순서를 지켜야 합니다.

## 서비스에서 조회하는 방법

학생의 전공과 입학년도에 맞는 행만 사용합니다.

```
program_id == 학생의 전공
admission_year_from <= 학생의 입학년도 <= admission_year_to
```

- 과목 X의 **선수과목**: `to_code == X`인 행의 `from_code`
- 과목 X **이후 과목**: `from_code == X`인 행의 `to_code`
- 선수 체인 전체는 이 관계를 반복해서 따라가면 됩니다.

## 알아둘 점

- **`coreq`는 순서가 없는 관계**입니다. 자료구조(`COME0331`)와 자료구조응용(`COMP0216`)은 같이 신청해야 하며, 한 줄만 기록했습니다. 화살표처럼 그리면 선후수로 오해됩니다.
- `official`은 2025 ABEEK 안내문 기준입니다. 원문의 "2012학번부터 적용"은 `note`에 남기고 적용 연도는 2023~2025로 한정했습니다.
- 원문 선후수 6쌍 중 `자료구조 → 자료구조프로그래밍`은 교육과정에 없는 과목이라 넣지 않았고, `프로그래밍기초 → 자료구조/자료구조응용`은 두 줄로 나눠 기록했습니다.
- `recommended`는 문서의 권장 이수 체계에서 가져왔고, 인공지능컴퓨팅 2026은 문서가 예시로 적은 흐름 일부만 담았습니다.
- "관계 없음"이 "선후수가 없다"는 뜻인지 "자료가 없다"는 뜻인지 구분되지 않습니다. 글솝과 첨단컴퓨팅연구는 특히 그렇습니다.
- `group_no`는 현재 모두 `1`입니다. "A 또는 B"가 필요한 OR 조건이 생기면 같은 `to_code`에 같은 `group_no`로 여러 줄을 추가합니다.


## #2 정규화에서 바뀐 점

- **`group_no` AND/OR 재검토**: 플랫폼SW&데이터과학의 종합설계프로젝트1(`ITEC0401`)은 선수 관계가 2건입니다(기초창의공학설계 `COMP0205`, 자바프로그래밍 `COMP0217`). 둘 다 `group_no: 1`이어서 "둘 중 하나(OR)"로 읽혔는데, 원문 선후수 표에서 서로 다른 행이므로 **둘 다 필요(AND)** 로 해석해 id 7의 `group_no`를 `2`로 바꿨습니다. 원문을 다시 확인하면 확정됩니다.
- 그 밖의 필드와 값은 바꾸지 않았습니다. 서비스 추천(초록선)은 계산 결과라 이 파일에 넣지 않습니다.
