# course_equivalents.json

## 이 데이터가 의미하는 것

**코드가 다른데 같은 과목으로 지정된 과목 쌍**(동일과목)을 담은 파일입니다. 한 줄이 구교과목 하나와 신교과목 하나의 대응이며 총 11건입니다.

출처는 학부 공지 "[필독] 2026학년도 신설(심화컴퓨팅전공,첨단컴퓨팅연구전공) 교육과정에 따른 동일과목 지정 현황"(2026-02-09)입니다. 공지에 따르면 동일 과목을 다시 수강하면 **재이수로 처리**되므로, 서비스가 같은 과목을 두 번 이수한 것으로 계산하거나 이미 들은 과목을 다시 추천하지 않도록 막는 데 사용합니다.

```
course_equivalents.json ──(old_code, new_code)── courses.json
                        └─(new_course_programs)── programs.json
```

## 서비스에서 쓰이는 기능

| 기능 | 사용하는 필드 | 쓰임 |
|---|---|---|
| 수강 이력 입력 (F03) | `old_code`, `new_code` | 구과목을 이수했다고 체크하면 대응하는 신과목도 "동일과목 이수"로 표시, 그 반대도 같음 |
| 추천에서 제외 (F08) | `old_code`, `new_code` | 한쪽을 이수했으면 대응하는 과목을 추천 후보에서 제외 (재이수 방지) |
| 학점 중복 방지 (F09) | `credit_changed` | 같은 과목은 한 번만 학점 인정. 총 학점이 다른 쌍은 안내 문구 표시 |
| 과목 검색 (F10) | `old_code`, `new_code` | "데이타베이스"를 검색해도 "데이터베이스"가 함께 나오도록 연결 |
| 과목 상세 (F07) | `note`, `source_url` | "동일과목: ○○" 표시와 공지 링크 |

## 필드

| 필드 | 타입 | 설명 | 예시 |
|---|---|---|---|
| `equivalent_id` | number | 기본 키 | `6` |
| `old_code` | string | 구교과목 과목코드 (`courses.json` 참조) | `"COMP0322"` |
| `new_code` | string | 신교과목 과목코드 (`courses.json` 참조) | `"COME0427"` |
| `relation` | string | 관계 종류. 지금은 `same_course`(동일과목)만 있음 | `"same_course"` |
| `old_credit_sys` / `new_credit_sys` | string | 각 과목의 학점체계 (`courses.json`과 같은 값) | `"3-2-2"` / `"3-3-0"` |
| `credit_changed` | boolean | 총 학점이 서로 다르면 true | `false` |
| `new_course_programs` | string[] | 신교과목을 개설한 전공 | `["adv_computing","adv_research"]` |
| `new_course_grade` | number | 신교과목 기준 학년 | `3` |
| `effective_from` | string | 적용 시작 학기. 학년별로 순차 적용 (1학년 2026-1, 2학년 2027-1, 3학년 2028-1, 4학년 2029-1) | `"2028-1"` |
| `old_placement` / `new_placement` | string | 공지에 적힌 구·신 과목의 교과구분과 학년·학기 | `"전공 3학년 2학기"` |
| `source`, `source_url` | string | 근거가 된 공지와 주소 | |
| `note` | string \| null | 보충 설명 | `"총 학점이 다름(6→3학점)…"` |
| `counts_for_required` | boolean \| null | 구과목을 이수하면 신과목의 전공필수를 충족한 것으로 보는지. 공지에 없어 전부 `null`(학과 확인 필요). **#2에서 추가** | `null` |
| `credit_recognition` | string \| null | `credit_changed`가 true인 2건의 학점 인정 방식. 공지에 없어 `null`. **#2에서 추가** | `null` |
| `applies_to_years` | number[] \| null | 이 대응을 적용하는 입학년도. 원문에 학번 기준이 없어 `null`. **#2에서 추가** | `null` |

## 서비스에서 활용하는 방법

1. 학생이 이수한 `course_code`마다 이 파일에서 `old_code` 또는 `new_code`가 같은 행을 찾습니다.
2. 대응 과목도 "이수한 것과 동일"로 취급해 추천 후보와 학점 합산에서 중복되지 않게 합니다.
3. `credit_changed`가 true인 쌍은 학점 차이를 안내합니다.

## 알아둘 점

- **이 파일은 2026학년도 신설 심화컴퓨팅·첨단컴퓨팅연구전공 기준 공지**의 11건뿐입니다. 다른 전공·연도 사이의 대체 인정 규칙이나 타 전공 학점 인정은 이 파일에 없습니다.
- 공지에는 "대체 인정"이나 "폐지·변경"을 따로 구분한 표가 없고, 이 표가 전부입니다.
- **총 학점이 다른 쌍이 2건**입니다. 프로그래밍기초(6학점) → 기초프로그래밍(3학점), 종합설계프로젝트2(4학점) → 인공지능융합응용특강(3학점)입니다. 학점을 어떻게 인정하는지는 공지에 없으니 서비스는 "학점 차이가 있음"만 안내하고, 계산은 학과 확인 후 정해야 합니다.
- 공지는 "동일 과목을 다시 수강하면 재이수"라고만 적었습니다. **구과목 이수가 신교과목의 전공필수·졸업요건을 충족시키는지**(예: 프로그래밍기초 → 신 전공필수 기초프로그래밍)는 공지에 명시되어 있지 않아, 서비스는 "동일과목"으로 표시하는 데까지만 하고 요건 충족 판정은 학과 확인 후 반영하는 것이 안전합니다.
- `effective_from` 이후에 신교과목 기준이 적용됩니다. 적용 시기는 공지가 신교과목의 학년 기준으로 안내한 값을 옮긴 것이고, 학번별 적용 기준은 원문에 명시되어 있지 않습니다.
- 이전에 "자료구조응용 ↔ 자료구조실습"이 대체 관계인지 확인이 필요하다고 했는데, **이 공지의 대응 표에는 없습니다.** 따라서 이 쌍은 연결하지 않았습니다.


## #2 정규화에서 바뀐 점

- `counts_for_required`, `credit_recognition`, `applies_to_years`를 추가했습니다. 세 값 모두 공지에 근거가 없어 `null`이며, 학과 확인 후 채웁니다.
- `null`일 때의 기본 처리(이수 판정 #6): 구·신 코드 중 하나만 이수해도 같은 과목으로 보고 학점은 1회만 인정합니다. 학점이 달라진 2건은 확인 전까지 신과목 학점을 쓰고 "학점 차이 있음"을 안내합니다.
